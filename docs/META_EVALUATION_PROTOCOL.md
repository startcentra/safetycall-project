# v0.5 모델 비교 평가 프로토콜

## 실험 A/B/C의 분리
- A: 기존 v0.4의 유일한 `assessTriage()`; 60건 합성 데이터에서 측정한 기존 지표 **변경 없음**.
- B: `shouldCallMeta`가 켜진 발화만 Meta로 보내는 **Triggered Meta**. 현재 승인 단계는 코드+MOCK 테스트까지만. 실제 Live Meta 실측 지표는 **없음**.
- C: 모든 발화에 Meta를 보내 게이트의 미탐을 정량화하는 연구용 Full Context. **미구현·실행 금지(별도 비용 승인 필요)**.

## 편향·누수 방지
- 입력에는 현재까지 발화만 포함, 미래 발화/정답/분류 메타데이터를 포함하지 않는다.
- 60개 가상 사례 중 애매한 15건은 이진 F1에 섞지 않는다. 시나리오 계열별 분리 평가가 필요.
- LIVE 전향적 분석 결과만 실제 Meta 성능으로 명시한다. MOCK 값은 `assessTriage()`의 재표현이다.
- 비교 지표: TP FP TN FN, Precision Recall F1, 조기경고, 호출 트리거 재현율, P50/P95 지연, 사용 토큰, 비용.
- 모델이 위험하지 않다고 답변하더라도 기존 정책의 긴급 안내·송금 보류를 무효화할 수 없다.
- 단일 스냅샷의 모의 호출은 전체 통화의 조기개입 성능을 검증하지 않는다.

## 향후 소규모 LIVE 실험 절차 (미승인)
1. Meta 키·과금·접근권한을 사용자가 확인한다.
2. 유료 호출 총 건수와 예상 비용을 명시하여 별도 승인을 받는다.
3. 트리거 유형이 다른 가상 발화 중 최대 5개를 사전 선정한다.
4. 성공·실패 로그에는 키·실제 대화 전문을 남기지 않는다.
5. 성능 비교는 사전 선정된 고정 사례만 사용하며 결과를 꾸미지 않는다.
