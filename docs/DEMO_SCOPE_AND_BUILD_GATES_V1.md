# SafeCall — 최단 개발 경로 / 데모 요구사항 / 완료 게이트

> 해커톤 MVP 범위를 통제하기 위한 **계획**이며, 각 항목이 현재 구현되었다는 뜻은 아니다. 2026-10-28 기준 코드: v0.6.3 + OSS 표시. 기존 오프라인 테스트 기록 73개; 전체 Next.js 빌드와 Meta LIVE 검증은 미완료.

## 1. 2분 내에 보여줄 핵심 장면 1개

**부모 브라우저:** 합성 음성으로 '아들을 데리고 있다, 송금해라' → AI가 납치 **주장**·협박·금전 요구 구조화 → 공식 대응카드 기반 '송금하지 않기 / 가족 안전 확인 / 긴급 신고 안내' → 안전 확인 버튼.

**자녀 브라우저:** 실제 서버 MockCall 이벤트가 표시되고 선택(안전하다는 응답/도움 필요/지금 응답 불가) → 서버 Case가 갱신되고 부모 브라우저 화면이 실제로 변함. 미응답이면 테스트용 사전 등록 보조 확인자 화면으로 옮겨가는 분기.

**금융 브라우저:** 기존 서버 모의 송금 `HELD`/`CANCELLED`. 선택적으로 가상 카드 상태 `ACTIVE → LOCKED`가 기록됨. 모든 화면에 MOCK·실제 서비스 미연동 표시.

Meta 역할을 보여주는 별도 컷: 승인된 Meta LIVE 실험을 **실제 완료한 경우에만** 실호출 결과 표시. 승인되지 않았다면 MOCK으로 투명하게 표시하고 심사상 미충족 위험을 인정한다.

## 2. 화면은 세 개면 충분

1. **보호자 화면:** 가상 통화, 위험 증거, 지금 행동, 필요시 대사, 가족 확인 요청, 가상 금융 보호.
2. **자녀/승인된 연락 상대 화면:** 모의 전화 수신 UI, 응답 종류 선택, 현재 시뮬레이션임을 고지.
3. **개발자 패널:** 이벤트 타임라인, Meta LIVE/MOCK, 지수 변화, 출처 카드 ID, 버전·오류·비용 상태.

Discord·실제 전화·새 모바일 APK·AR 안경·소셜 그래프 조회는 핵심 MVP에서 제외. 브라우저 모의 전화가 안정화되면 Discord는 **선택적** 어댑터로 고려.

## 3. 단계별 개발 순서 — 이전 단계 실패 시 기능 추가 중지

### Gate 0 — 실행 기반 확보 (최우선)

- `npm install`, Node.js 버전, `npm run typecheck`, `npm run build` 실제 성공(현재 미검증).
- 기존 `npm run test:offline` 73개 회귀 테스트 유지.
- 브라우저 `/lab/voice`, `/lab/replay`, `/simulator` 기동·기본 조작 확인.
- OSS 출처/라이선스 표기를 변경하지 않음.

### Gate 1 — 기존 치명 결함 해결

- 같은 통화의 Meta Spark/Voice 비용 `costSessionId` 공유.
- Meta 출력 토큰 상한과 `finish_reason` 검증.
- 예약 초과 정산/미확정 부채/활성 Kill Switch 처리.
- 긴 협박 발화 후 8개 평범한 발화에서도 미해결 근거 유지.

### Gate 2 — 가족 사칭 범죄 인식 + 근거 기억

- Meta 없이도 동작할 규칙/상태/근거 스키마, 발화별 `ACTIVE/DISPUTED/RESOLVED/RETRACTED`.
- 가족 위해 주장, 신고 방해, 금전 요구, 정상 가족 긴급전화, 교육 인용, ASR 오류 정정 테스트.
- Muse 구조화 의미 분석은 optional; 데이터 유출/비용·지연 통제.

### Gate 3 — 공식 교범 기반 코칭

- 검토된 최소 카드와 출처 레지스트리, 카드 선택 정책.
- `지금 할 행동`, `필요시 말할 문구`, `근거`, `긴급 안내` 분리.
- 실제 납치 가능성/미응답/진짜 위험에서는 신고 안내가 가족 확인보다 선행.

### Gate 4 — 단일 Case와 브라우저 모의 가족 확인

- `CaseCoordinator` + 안정적인 사건/통화/이벤트 ID.
- 실제 서버 모의 발신, 별도 자녀 화면 응답, 부모 화면 갱신.
- 중복 이벤트·동의 철회·만료·새 사건의 늦은 응답 방지.
- 실사용 전화번호/자동 교사 발신 없음.

### Gate 5 — 금융 보호 및 Meta 실제 검증 (별도 승인)

- 기존 가상 이체 보류 유지. 가상 카드 잠금은 부가 시연으로 추가하되 CardLock ≠ BankTransferHold 명시.
- Meta LIVE를 사용할 때만 명시적 승인·예산 상한·실제 로그 구분.
- 전체 시연 브라우저 E2E 자동화(의존성 도입은 빌드 검증 후), 세션 끊김/재시작 시험.

## 4. 평가에 필요한 사례 묶음

| 분기 | 반드시 확인할 결과 |
| --- | --- |
| A. 가족 사칭 + 송금 요구 | 근거 추출, 카드 선택, 독립 확인 시작, 실제 가상 상태 변경 |
| B. 실제 가족의 정상 급한 요청 | 강한 사기 단정/무단 연락 없음 |
| C. 납치 협박과 실제 위해 가능성 | 즉시 긴급 신고 안내, 검증을 기다리지 않음 |
| D. 자녀 미응답 | 안전 여부 UNKNOWN, 허용된 보조 확인 경로만 |
| E. 안전 응답 후 늦게 온 외부 메시지 | 버전 불일치 응답 버리고 검증 상태 과장 금지 |
| F. 중복 클릭/재시도/ASR 정정 | 한 번의 발신 작업, 정정된 위험 기록, 안정된 예산 |
| G. 모델/네트워크 중단 | 기본 안전 코칭 유지, 잘못된 가상 금융 행위 없음 |
| H. 부정문·역할극·교육 영상 | 내용의 인용을 실제 납치 요구로 확정하지 않음 |

## 5. 성공 기준 (정량/정성, *목표*일 뿐 완료 아님)

- **E2E:** A~H 중 P0 6종을 실제 브라우저 자동화 또는 수동 재현 기록으로 입증; Case 이벤트와 화면 반영 모두 확인.
- **모의 연락:** 명시적 승인된 가상 대상에만 발송, 새 사건/동의 철회/중복 요청에서 0건 오발신.
- **코칭:** 근거 없는 '납치 확정', '안전 확정', '신고하지 마세요' 발화 0건을 목표로 안전성 리뷰.
- **평가:** 현재 합성 60건의 기준 Recall 86.7%, FPR 6.7%, 위험 행동 이전 1/30 기록을 보존하며 새 독립 테스트와 별도 보고.
- **신속성:** `발화 종료 → 코칭 표시`와 `가족 확인 요청 → 모의 수신` 지연을 계측; 실측 전 목표 성능 선언 금지.
- **Meta:** Meta 사용 여부, 모델 버전, 실측 토큰/비용/지연을 표로 구분. 승인 전 실제 호출 0회.
- **완료 판단:** 코드 스크린샷이 아니라 앱에서 버튼→서버 이벤트→상태 변화→다른 화면 반영을 실제로 확인.

## 6. 지금은 만들지 않을 것

- 기존 휴대전화·WhatsApp 개인 통화 감청, 보호된 OS 전화 오디오 우회.
- 실제 교사·직장 동료 자동 발신, 경찰 112/911 자동 신고.
- 실제 카드사/은행 연동, 무단 카드 잠금, 다른 앱 강제 종료.
- 새 모델 훈련, Llama 온디바이스 최적화, Discord 의존 핵심 흐름.
- 대규모 사례 무단 스크래핑, 저작권 미검토 통화 녹취 수집.
- 여러 위험 분류 엔진 추가, 마이크로서비스 분해, 고가 인프라.
