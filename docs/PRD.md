# SafeCall Guardian — Product Requirements Document v1.0

> 작성 기준: 2026-10-27. 상태: **M0 정의 완료 / M1 골조와 M2 규칙 기반 데모 작성 중**. 아래 전체 MVP 요구사항은 아직 구현 사실이 아닙니다. 실제 Meta API 연결은 미구현입니다.

## 1. 문제 정의
보이스피싱 의심 통화에서는 긴급성 압박, 기관 사칭, 고립 유도, 송금·인증정보 요구가 복합적으로 등장한다. 단순 탐지·확률 점수보다 사용자의 현재 의사결정에 맞는 **짧고 실행 가능한 코칭과 행동 결과 확인**이 필요하다.

## 2. 제품 목표
가상의 전화와 가상의 금융 거래를 결합해, Meta AI가 대화 위험 신호를 추출하고 정책 엔진이 가상 거래 보류를 결정하며, 사용자의 행동에 따라 다음 안전 코칭을 갱신하는 시스템의 기술적 가능성을 시연한다.

**해커톤 주제:** Build for Your World. **트랙:** Indie Developer (개인).

## 3. 핵심 가설과 차별성
- 가설: 대화 속 위험 행동 유도와 실제 사용자의 거래 시도를 결합하면 적절한 시점에 구체적인 조언을 제시할 수 있다.
- 차별성: `Detection → Policy → Action Coaching → User Choice → Transaction State → Next Coaching`의 폐회로 워크플로.
- 시험용 데모만으로 실제 보이스피싱 예방 효과나 모델 정확도를 주장하지 않는다.

## 4. 대상과 범위
- 해커톤 시연 이용자: 시뮬레이션에서 가상 통화와 가상 송금을 체험한다.
- P0: 모의 통화, 실제 Muse Spark 분석, 안전 정책, 상태별 코칭, 가상 계좌/거래 보류·취소, 행동 결과 타임라인, 정상 흐름 테스트.
- P1: 가상 기관 주장 검증, 확인된 공공 지침 인용, 긴급협박 추가 시나리오, 동의 기반 마이크 입력.
- P2: 연속 오디오 스트리밍, 추가 언어, 공식 공개 신고정보 연계(연동 허가 확인 시에만).
- P3: 실제 휴대전화 통화 접근, 실제 금융기관 거래 통제(법적·계약적 별도 권한 필요).

## 5. 주요 사용자 시나리오 (은행 사칭)
1. 사용자가 `은행 사칭 시나리오`를 시작한다.
2. 사전 제작된 가상 발화가 순서대로 전달된다.
3. Meta AI가 발화를 분석해 `MONEY_TRANSFER_REQUEST`, `URGENCY_PRESSURE` 등의 위험 신호 및 **미검증된** 상대방 주장을 반환한다.
4. 정책이 코칭 카드를 선택한다: '송금하지 말고 독립된 공식 경로로 확인'.
5. 사용자가 `DEMO-USER-001`에서 `DEMO-TARGET-002`로 가상 이체 시도.
6. 은행 서비스는 정책 결정이 `HOLD_FOR_REVIEW`이면 서버 측에서 보류하고 **잔액을 이동시키지 않는다**.
7. 사용자가 취소 또는 가상 검증을 선택한다.
8. 거래·사건 상태를 갱신하고 후속 코칭을 제공한다.
9. 사건 타임라인에 발화, 탐지, 정책, 행동, 거래 상태가 기록된다.

## 6. 긴급상황 안전 설계
- 납치·폭력 위협이 의심되면 '보이스피싱이 확실하다'고 안내하지 않으며, AI 분석 완료를 기다리지 말고 **112 신고를 우선 안내**한다.
- 실제 신고·전화 발신·송금·강제 통화종료는 자동 수행하지 않는다.
- 상대방 실제 위치 추적, 통신망 해킹, 민감정보 수집을 기능에 포함하지 않는다.
- 공식 대응 지침은 직접 확인한 출처·확인일·사용 조건과 연결한다. 확인되지 않은 논문은 인용하지 않는다.

## 7. 제품 수용 기준 (MVP)
- 실제 Meta API 호출 성공을 데모 모드와 확실하게 구별하고 증명한다.
- 중요한 발화 이벤트 이후 코칭이 갱신된다.
- 거래 보류는 서버에서 강제한다. 프런트엔드의 메시지만으로는 완료로 인정하지 않는다.
- 보류 중 잔액 변화가 없고 같은 요청을 재전송해도 중복 이체가 발생하지 않는다.
- 사용자의 취소 행동이 거래 상태와 후속 코칭을 바꾼다.
- Meta 응답 오류에도 안전 안내가 사라지지 않는다.
- 정상 통화·정상 송금과 긴급협박 상황을 별도로 테스트한다.

## 8. 성공 측정 및 제약
| 지표 | 측정 방법 | 목표 해석 |
|---|---|---|
| 코칭 지연 | 위험 발화 수신→코칭 렌더 시간 | 실제 측정값 사용 |
| 분석 지연 | Meta 요청→응답 시간 | 실제 측정값 사용 |
| 위험 거래 보류 | 가상 송금이 잔액 불변으로 보류되는지 | 테스트 100% 통과 목표 |
| 정상거래 오탐 | 정상 시나리오 내 불필요한 보류 횟수 | 개별 결과 공개 |
| 안전 실패 | AI 오류·긴급상황 시 안전 안내 누락 | 테스트 0건 목표 |

## 9. 비기능 요구사항
- 신규 기능은 2026-10-26~11-04 사이에 만든 작업만 시연한다.
- 공개 GitHub와 3분 작동 데모 영상 준비, 제출 포털 등록.
- API 키는 서버 비밀 환경변수로 관리, Git 이력 공개 전에 전체 점검.
- 현재 가상 발화와 사건 타임라인은 서버 메모리에 임시 보관(최대 30분)하며 실제 통화 및 개인정보는 수집하지 않는다. 정식 출시 이전에 수집/보존 정책 별도 검토.
- 장애 발생 시 명확하게 실패를 표시하고 검증되지 않은 결과를 과장하지 않는다.

## 10. 마일스톤 / Go-No-Go
- M0 (10/27): 이 PRD, 아키텍처, 계약, 안전 정책 초안 확정.
- M1 (10/27–28): Next.js 실행, `/api/health`, 빌드/테스트.
- M2 (10/28–29): 가상 발화, Mock Bank, 데모 워크플로 첫 수직 기능.
- M3 (10/29–30): Meta API 실제 연결 (지연 시 다른 확장 기능 중지).
- M4 (10/30–31): 이벤트별 행동 코칭과 안전 우선순위.
- M5 (11/1): 실제 서버 정책으로 가상 송금 보류·취소, 사건 타임라인.
- M6 (11/2): 정상/긴급/장애 테스트, P1은 시간 남으면 추가.
- M7 (11/3–4): 배포, 보안감사, 3분 영상, 공개 저장소·최종 제출.

## 11. M0/M1의 실제 구현 상태
M1 웹앱은 **현재 운영 상태 표시 + Health API**까지만 구현한다. 대화·Meta 분석·거래·코칭은 계약 일부가 준비되었으나 미구현이다.


## 12. 후속 조사 설계 제안 (2026-10-27, **기능 승인 대기**)
- 기존 M0–M7 계획은 현재 기준을 유지한다.
- 위험 신호 + 정상성 검토 + 행동 이벤트의 **Adaptive Risk-Gated Intervention** 설계, 발신 번호·목소리의 신원 인증 오해 방지, 고위험 트리거 시 정책 재검사를 제안한다.
- Meta Ray-Ban Display 전용 `/glasses` UI 및 브라우저 시뮬레이터는 **P1 승인 후보**, 실제 안경·실제 전화 연결은 **P3 별도 검증 후보**다.
- 자세한 후보 비교/기술 근거/승인 게이트: [ADR-0002](ADR-0002_ADAPTIVE_INTERVENTION.md). 실제 코드 반영이나 개발 우선순위 확정이 아니다.


## P0/P1 제품 보강 — 입력 소스 신뢰 경계 (2026-10-27, 구현 제안)

- P0: 앱이 제어하는 가상 통화/허용된 녹음만 오디오 스트리밍 실험 소스로 사용; 키워드 탐지는 텍스트 전사 후에 작동한다.
- P0: 위험 행동 이벤트는 의심 표현 부재 시에도 정책 검사를 시작한다.
- P1: 실제 전화에서는 확보 가능한 수신 정보와 사용자가 직접 제공한 설명을 기반으로 한 **수동 코칭 모드**를 설계한다. 이는 실시간 상대방 음성 분석이 아니다.
- P1: Android 오버레이 및 Meta Ray-Ban Display는 **출력 UI**로 추가할 수 있으나 통화 오디오 접근 권한을 부여하지 않는다.
- P2: 자체 VoIP 또는 사업자 공식 연동은 안전·법적 승인과 별도 개발 범위를 필요로 한다.
- 모든 모드에서 동의 상태, 오디오 소스, 분석 모드, 마지막 반영 발화 번호를 화면·기록에 정확하게 노출한다.

근거 및 검증 우선순위: [ADR-0004](ADR-0004_AUDIO_SOURCE_AND_REAL_CALL_BOUNDARIES.md). **실제 기능은 아직 구현되지 않았다.**


## 2026-10-27 구현 범위 고정 — 리팩토링 v0.3

- Next.js 웹앱과 1차 위험 분석기 `assessTriage()`는 각각 하나만 사용한다. **영상/유튜브 사례, Lab, Simulator는 입력 경로일 뿐 새 탐지 엔진이 아니다.**
- 1차 연구 실험은 허가된 공개 자료의 위험 수법을 개인정보 없는 합성 텍스트로 재구성해, 순차 발화별 위험·심리적 조작·코칭 후보를 평가한다.
- Meta Muse Spark 실호출, 원음 전사, 안경 표시, 실제 전화 수신, APK 등은 이번 리팩토링에 포함되지 않는다.
- 현재 코칭은 검증된 공식 근거 기반 완성물이 아니라 데모 규칙이다. 실제 서비스 성능을 주장하지 않는다.
- [현재 기준 아키텍처](ARCHITECTURE.md)와 [리플레이 데이터 흐름](REPLAY_DATA_FLOW.md)을 우선한다.
