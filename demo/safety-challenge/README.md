# SafeCall Safety Challenge — 순수 가상 시뮬레이션

**이 폴더는 SafeCall Care v0.9.0의 로컬 전용 데모 앱입니다.** 전화·음성녹음·Meta API·은행·경찰·외부 문자/알림 기능을 전혀 호출하지 않습니다. 모든 대사, 가족 응답, 금액은 허구입니다. 실제 사용자에게 효과가 입증된 제품이 아닙니다.

## 1분 실행 (Node.js 22 이상)

```bash
# 전체 프로젝트 최상위 폴더에서 실행
npm run demo:safety
```

브라우저에 **http://127.0.0.1:4173** 입력. 서버는 루프백 주소에만 바인딩하므로 인터넷으로 공개되지 않습니다. 다른 npm 패키지를 설치할 필요가 없으며, 기존 Next.js 빌드도 필요하지 않습니다. 단, Node.js 22의 `--experimental-strip-types`가 필요합니다.

다른 앱에서 4173 포트를 쓰고 있다면:

```bash
SAFECALL_DEMO_PORT=4174 npm run demo:safety
```

Windows PowerShell에서는 `$env:SAFECALL_DEMO_PORT="4174"; npm run demo:safety`.

## 0.9: 사건 종료 후에도 가능한 회복 체크리스트

B/C 모드에서 **사후관리 안내**를 누른 뒤 피해 유형(`PAYMENT`, `CREDENTIALS`, `REMOTE_ACCESS`, `IDENTITY`, `UNKNOWN`)을 선택하세요. 해당 국가(KR/US)의 공식 공개 자료 링크와 단계별 선택이 표시됩니다. `미완료 / 완료했다고 표시 / 해당 없음`으로 상태를 기록할 수 있습니다. `사건 종료` 이후에도 회복 단계는 별도 상태로 계속 갱신되며 기존 위험 판단은 바뀌지 않습니다.

`POST /api/recovery/event`는 `runId`, `expectedVersion`, `expectedRecoveryVersion`, `eventId`, `type`, `pathId`와 이벤트 유형별 `stepId`, `status`를 검사합니다. 이벤트 ID 중복 재전송은 동일 내용만 중복 처리하며, 다른 사건/유형/단계/오래된 버전은 차단됩니다. 서버 재시작 시 기록은 사라집니다. 로컬 단일 데모여서 실사용 인증·영속성 기능이 없습니다.

새 합성 시나리오 `otp`, `remote`, `uncertain`이 추가되었으며 기존 `kidnap`, `bail`, `benign`은 유지합니다. `AUTHORITY_CLAIM` 또는 `SECRECY`처럼 기존 엔진에서 실제 발견한 신호만 있을 때 B/C에 비단정적 저강도 안전 안내가 제공될 수 있습니다. 이 안내는 위험 판정이나 금전 보호 실행이 아닙니다.

`npm run test:demo`는 49개 오프라인 API·정책 테스트, `npm run test:offline`은 173개 전체 테스트를 수행합니다. 브라우저 시각적 E2E/Next.js 빌드·타입 검사/외부 연동은 확인하지 않았습니다.

## 0.8: 통화가 없어도 가능한 케어 시작

- B/C 모드에서는 상단의 **통화 내용을 몰라도, 지금 도움을 시작할 수 있습니다**에서 사용자가 걱정되는 상황을 선택할 수 있습니다.
- 이 선택은 `POST /api/care/check-in`으로 같은 가상 사건에 기록하며, **발화 근거·실제 위험 점수로 취급하지 않습니다**.
- Care Plan은 기존 `selectLiveGuidance()` 판단을 받아 행동 안내를 정리합니다. 신체 위해 위험 근거가 있으면 가족이 안전하다고 답하더라도 긴급 안내가 최상단을 유지합니다.
- 가족의 응답과 미응답은 우선순위 판단을 덮어쓰지 않고 **별도의 미인증 가상 응답**으로 화면에 나타납니다.
- 케어는 실행 권한을 갖지 않습니다. 실제 외부 문자, 통화, 경찰 신고, 금융 행동은 전혀 발생하지 않습니다.
- `checkInBeforeObservedMoneyRequest`는 사용자가 **가상 대본에서 관찰된 송금 요구보다 먼저 버튼을 눌렀는지**만 기록합니다. 피해 예방 성공률 또는 실제 조기 탐지 성능이 아닙니다.

## 실제로 움직이는 시연 방법

1. 먼저 상단에서 *가족이 위험하대요*, *돈·인증번호를 요구해요*, 또는 *잘 모르겠지만 수상해요*를 선택해 통화 없이 안내를 시작할 수 있습니다 (B/C만).
2. **가상 사건** `자녀 납치 주장` 선택, 실험 모드 `C · 코칭 + 가상 가족 확인` 선택, `새 시뮬레이션` 클릭.
3. `다음 발화 보기`를 한 번씩 누릅니다. 화면에는 그 시점까지 공개된 대사만 나타납니다.
4. `가상 가족에게 확인 요청`을 누른 뒤 `자녀 응답 화면 열기`를 클릭합니다.
5. 별도 자녀 창에서 `안전하다고 자가 보고`, `도움이 필요함`, `확인할 수 없음` 중 하나를 선택합니다. 부모 창이 **Server-Sent Events(SSE)**로 갱신됩니다.
6. 부모 창에서 `송금 보류`, `긴급 도움 선택`, `가상 송금 시도`, `사후관리 안내`를 눌러 선택 기록을 확인합니다.
7. `사건 종료` → 다른 모드(A/B)로 다시 진행하여 UI 하단에서 이전 가상 실행을 비교합니다. `결과 JSON 보기`를 눌러 가상 기록을 내려받을 수 있습니다.
8. `정상적인 가족 연락` 시나리오에서 과도한 경고가 나오지 않는지 확인합니다. `가족 긴급 송금 사칭` 사례에서는 송금 요구가 나오기 전 가족 주장의 독립 확인 코칭이 나타날 수 있습니다.

### 실험 모드

- **A · 일반 경고:** 기존 규칙 기반 위험 지수만 표시. 행동 카드/가족 확인 없음.
- **B · 행동 코칭:** 기존 `selectLiveGuidance()` 출력과 실제 사건 근거를 표시. 가상 가족 확인 불가.
- **C · 코칭 + 확인:** B + 서버 메모리에 실제로 기록되는 가상 가족 확인 요청/응답.

**중요:** 이는 모드별 사용성 흐름을 비교하는 도구이지, 실제 참가자들이 사기를 덜 당했다는 증거가 아닙니다. 버튼 클릭을 '실제 송금 방지 성과'로 해석하지 마세요.

## 실제 활용 모듈

```
Node HTTP / SSE (이 데모의 신규 코드)
   ├── Fictional fixed-script scenarios
   ├── v0.6.6 Case Coordinator (src/modules/case/index.ts)
   │     └── 기존 assessTriage() / Risk Evidence Checkpoint
   ├── v0.6.6 selectLiveGuidance() / 공식 출처 기반 Action Card
   ├── Care Plan / concern check-in (new v0.8 mock policy)
   └── MOCK family confirmation / simulated user choices
```

이 시연은 기존 위험 엔진을 복제하지 않습니다. `Meta`라는 이름을 표시하면서도 실제 Meta 모델을 호출한 것처럼 행동하는 데모가 아닙니다. **provider=`SCRIPTED_MOCK`, metaCalled=false, realMoneySent=false**를 서버 상태에 명시합니다.

## 제약과 보안 경계

- 서버는 단 하나의 가상 사건을 메모리에 보유합니다. 새 시뮬레이션은 두 창의 기존 사건을 함께 대체합니다. 서버를 끄면 데이터가 사라집니다.
- 자녀 창은 신원 인증이 되지 않습니다. `SELF_REPORTED_SAFE`는 기기 또는 사람의 안전을 증명하지 않습니다. 미응답도 납치의 증거가 아닙니다.
- 로컬 개인 시연 전용. 인증, 다중 사용자 격리, 외부 배포, 연락처 등록, 실제 결제 차단, 가족 안전 확인 신뢰 모델은 미구현입니다.
- 음성을 듣거나 전사하지 않습니다. `다음 발화 보기` 버튼을 통해 이미 검수한 가상의 텍스트가 단계별로 나타납니다.
- 위험 지수는 규칙 기반 임시 점수이며 사기 확률이 아닙니다. 긴급기관 안내는 실제 신고를 실행하지 않습니다.
- 기존 Next.js 웹 앱과는 별도의 **독립 실행형 로컬 데모**입니다. 전체 Next.js 빌드·브라우저 E2E 미검증을 해결한 것은 아닙니다.
- 이 데모는 실제 위기상황에서 사용하지 마세요. 긴급한 위험이 있다면 현지 긴급기관을 직접 이용하세요.

### v0.8 미검증 목록

- Next.js `build`/`typecheck`/기존 앱 브라우저 E2E: 기존 결정대로 실행하지 않음.
- 독립 Node 데모의 HTTP/SSE 자동 테스트는 통과함. 이 환경의 Chromium은 로컬 호스트 접근이 관리자 정책으로 차단되어 **실제 시각적 브라우저 E2E도 미완료**.
- Meta API 실제 호출, 타인 인증, 실제 송금·음성 접근·기관 연락은 불가능하거나 미구현.
- 기존 합성 데이터의 **피해 행동 이전 자동 예방 코칭 0/30** 수치는 이 버전에서 다시 측정한 개선 성과가 아님. 사용자가 자발적으로 케어를 요청하는 별개 흐름을 추가했을 뿐임.
